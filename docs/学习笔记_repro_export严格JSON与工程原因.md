# 学习笔记：`repro` 严格 JSON 导出（`repro/export.py`）

本文说明仓库里 `src/qchem_stack/repro/export.py` 的职责，以及**为什么**要单独做一层“严格 JSON”转换，便于读源码时建立工程上下文。

---

## 1. 这个模块是做什么的

`repro` 通常指一次计算或一次实验的**可复现性元数据**：依赖版本、配置快照、路径、哈希等。它们往往需要：

- 写入文件（落盘、归档）；
- 通过 HTTP API 返回给客户端或其它服务；
- 被非 Python 环境（浏览器、Go/Java 服务、严格 JSON 校验器）消费。

`export.py` 提供两条主入口：

- `repro_dict_for_strict_json`：把嵌套的 `dict` 等结构**递归转成只含 JSON 原生类型**的纯 Python 结构；
- `repro_json_dumps`：在上一步之后调用标准库 `json.dumps`，并显式使用 `allow_nan=False` 等参数，得到**可在不同栈之间交换**的 JSON 文本。

不支持的类型、非有限浮点数、循环引用会抛出 `ReproExportError`（定义见 `src/qchem_stack/exceptions.py`），而不是静默降级。

---

## 2. 为什么需要单独模块（工程动机）

### 2.1 可复现信息必须是“可交换、可校验”的

`repro` 的价值在于：别人拿到同一份序列化结果，能对照环境、复跑、审计。这要求输出是**标准 JSON 语义下的对象树**（对象、数组、字符串、数字、布尔、`null`），而不是一堆“看起来像字符串、实则已丢信息”的占位符。

把规则集中在一个模块里，可以避免每个业务调用点各写一套 `dumps` 参数和类型分支，减少行为漂移。

### 2.2 避免 `json.dumps(..., default=str)` 掩盖错误

常见省事写法是给 `json.dumps` 传 `default=str`：遇到无法序列化的对象就转成字符串。

副作用是：**导出表面成功，语义已经错了**。例如下游以为是结构化字段，实际得到 `"<SomeObject object at 0x...>"` 这类不可解析、不可比对的内容。问题被推迟到消费端甚至人工排障时才暴露，成本高，也不利于合规与审计。

本模块的策略是：**不支持就明确报错**，在“离开 Python 进程”之前失败，定位路径信息也在转换逻辑里统一处理。

### 2.3 科学计算里常见的浮点与 JSON 规范

量子化学与数值代码中容易出现 `NaN`、`Infinity`。标准 JSON **没有**这些字面量；Python 的 `json` 在默认模式下可能写出扩展形式，但**其它语言的解析器或严格校验**常会拒绝。

因此模块在浮点上用 `math.isfinite` 检查，并在 `json.dumps` 时使用 `allow_nan=False`，与“只写 RFC 友好 JSON”的目标一致。

### 2.4 结构坏数据：循环引用与 Python 特有类型

- **循环引用**：若 `repro` 意外形成环， naive 递归或默认序列化可能栈溢出或难以诊断；本模块用容器 `id` 跟踪正在访问的对象，在环上抛出带路径信息的错误。
- **`pathlib.Path`**：不是 JSON 类型，需要稳定地变成字符串。
- **NumPy 标量与数组**：在科学代码里极常见，但不是 JSON 原生类型；模块在可选依赖存在时把标量 `.item()`、数组 `.tolist()` 后再递归，使结果仍是纯 JSON 可表示的树。

---

## 3. 本模块在设计上“保证什么”

用一句话概括：**在持久化或对外 API 之前，用同一套规则把 `repro` 变成严格、可移植的 JSON 数据，而不是依赖隐式转换把问题推迟到下游。**

具体包括（实现细节以源码为准）：

- 仅允许落到 JSON 原生类型（及少量显式约定的转换，如 `Path`、NumPy）；
- 拒绝非有限浮点数；
- 检测并报告循环引用；
- `json.dumps` 侧与 `allow_nan=False` 对齐，避免写出非标准数值字面量。

## 4. 读源码时的建议顺序

1. 阅读 `src/qchem_stack/repro/export.py` 的模块文档字符串与两个公开函数；
2. 理解递归函数 `_to_json_serializable` 中对 `dict` / `list` / `tuple` 的 `try/finally` 与 `_seen` 的作用（环检测与离开子树时清理）；
3. 对照 `ReproExportError` 的语义，思考在业务代码里应在哪一层捕获并转化为用户可见错误。
