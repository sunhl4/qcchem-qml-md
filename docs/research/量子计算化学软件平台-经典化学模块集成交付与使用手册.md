## 1. 交付概述

### 1.1 文档性质

本文是经典化学模块的**集成交付说明**，同时承担**功能说明书**与**操作使用手册**的职责。正文材料均来自本仓库已经落地的实现与文档，包括统一经典接口说明、驱动与能力位说明、chem 模块技术参考、SCF / 活性空间 / 嵌入配置说明、双线路 PreQuantumInput 契约、Phase A 实施清单、第二期工作计划、示例测试说明，以及站内 chem / solvers / dual-ingress 相关页面。文中路径、字段名与命令以当前仓库为准；若个别叙述与源码或加载期校验行为不一致，以源码为准。

### 1.2 交付对象

交付对象是量子计算化学软件平台中的经典化学层，对应包路径 `qchem_stack.chem`。该层位于配置加载之后、量子算法编排之前，负责把分子问题变成下游可消费的平均场参考、活性空间积分与量子比特哈密顿量。用户侧主要通过实验 YAML 与管线入口使用；集成侧通过 `ChemIntegralSolver` 注册表与 bridge 交换物扩展。

### 1.3 交付结论

本期交付完成后，经典化学层达到以下状态：

第一，统一经典入口已经可用。`ChemIntegralSolver` 协议、`create_solver` 工厂与 `SolverCapabilities` 能力门控构成多后端接入面；内置驱动为 `pyscf`、`psi4`、`precomputed`，并可通过 Python entry point 组 `qchem_stack.chem_solvers` 挂载第三方求解器，无需改动编排内核。

第二，生产主路径以 PySCF 为准，从 `ExperimentConfig` 经平均场桥接收口到 `PreQuantumInput`，具备单元与集成测试、代表配置样例与教程脚本支撑。Phase A 要求的经典对照接口、`driver_meta` 最小字段集、活性空间 manual/CAS 统一入口均已落地。

第三，Psi4 可作为可选次路径走同一 pre-quantum 契约，用于跨程序 HF 对照与代表嵌入样例。部分高级数值核（例如 AVAS、NEVPT2）在 Psi4 路径上通过导入分子轨道后委托共享核完成，相关事实写在能力位与 `capability_notes` 中，不对外宣称与 PySCF 全方法数值等价。

第四，在线 SCF 与离线预计算 bundle 在量子阶段前统一收口为同一 `PreQuantumInput`（schema `pre_quantum_input_v1`）。下游量子算法、协议与作业层按该契约消费，不应再区分经典结果来自哪家程序或是否现场计算。

第五，配置即契约。非法的驱动与嵌入、活性空间组合尽量在 `load_experiment_config` 阶段拒绝，并给出与能力位相关的错误信息，降低“跑到一半才发现后端不支持”的调试成本。

## 2. 交付背景与目标

### 2.1 为何必须单独交付经典层

量子阶段（VQE、ADAPT、QPE 等）依赖一组稳定的经典前置产物：分子几何、电荷与自旋多重度、基组、平均场参考轨道与能量、活性空间选取结果、分子轨道或原子轨道表象下的积分，以及用于对照的经典基准（HF、MP2、CCSD、CASCI 等）。若这些前置步骤接口不统一、元数据不可审计、示例不可回归，则后续量子算法深化会反复返工，Methods 写作与跨程序对照也缺乏锚点。

行业实践上，电子结构程序（PySCF、Psi4 等）仍是量子化学—量子计算工作流的真理基线来源。平台竞争焦点已从“能否跑通一次 VQE”转向工作流可信度、后端可替换性与结果可审计性。第二期工作计划据此将交付重心放在经典计算化学层，而不是并行铺开全部量子算法扩展。

### 2.2 本期目标

| 编号 | 目标 | 可交付用途 |
|------|------|------------|
| G1 | 落地 `ChemIntegralSolver` 统一经典入口 | 多后端扩展、第三方插件 |
| G2 | 完成 PySCF 主路径生产闭环（含 Phase A） | CI、parity、Methods 字段 |
| G3 | 证明 Psi4 可选后端可走同一 pre-quantum 契约 | 跨程序对照、合作方接入 |
| G4 | 提供分层配置示例与教程脚本 | 入门、演示、冒烟 |
| G5 | 能力矩阵与差距可追溯 | 后续 backlog、对外说明 |

### 2.3 与第一期、第三期的关系

第一期调研与架构设计确立了分层参考架构、配置即契约与可机读 repro 等原则，经典层对应 Chemistry drivers / adapters 与 pre-quantum build。第二期（2026 年 7–8 月）在此骨架上完成可验收交付：7 月侧重 PySCF 主路径与入门示例，8 月收口多后端、嵌入代表路径与说明定稿。第三期建议重心在量子算法广度、缓解执行模型、编译与云作业等，不在本文义务范围内，但本期能力差距表为其提供输入。

### 3.2 范围外

本期不交付或不宣称以下内容：闭源程序（ORCA、Gaussian、Q-Chem）数值主路径；与 Quantinuum Nexus 或商业化学内核的数值等价；全自动 AVAS 作为生产默认、NEVPT2/AC0 作为默认生产路径；量子编译、shots 缓解、云作业闭环本身（示例 YAML 可触达下游，但不列为经典模块主交付）；工业级 Fe4N2 等大体系一键案例（仓库仅有小分子可跑样例与占位说明）。

### 3.3 与上下游分界

```text
config（YAML → ExperimentConfig，加载期校验）
        ↓
chem（本模块：SCF / 积分 / 嵌入 / PreQuantumInput）
        ↓
orchestration → quantum / protocols / backends / jobs / repro
```

编排层不得为选路而直接 `import pyscf` 或 `import psi4`。下游只消费 `ClassicalMeanFieldReference`、`CanonicalActiveSpaceIntegralPack`、`PreQuantumInput` 等交换物。自 v0.6.0 起，历史 `PySCFDriver` 已移除，新代码一律走 `ChemIntegralSolver` + bridge。

## 4. 模块功能说明

### 4.1 功能总表

| 功能域 | 说明 | 主要入口 |
|--------|------|----------|
| 多后端平均场 | 按 `scf.driver` 选择求解器，完成 RHF/ROHF/UHF；PySCF 侧含周期性等扩展 | `create_solver` → `compute_mean_field` |
| 平均场桥接 | 将各后端结果规范为统一 reference，附带可审计 `driver_meta` | `classical_mean_field_via_solver_bridge` |
| 活性空间 | `cas` / `manual` / `avas`（及 stub）策略；轨道数与电子数校验 | `active_space` 配置 + pre-quantum 构建 |
| 费米子映射 | Jordan–Wigner、Bravyi–Kitaev、对称性守恒 BK | 活性空间映射字段 |
| 嵌入 | `none` / `dmet`（含 Schmidt）/ `projection` / `plugin` | `embedding.mode` |
| 双线路输入 | 在线 SCF 与离线 precomputed bundle | `resolve_pre_quantum_path` |
| 经典对照 | HF/MP2/CCSD/CASCI 等结构化 benchmark | `classical_benchmarks` |
| 能力门控 | 加载期按 `SolverCapabilities` 拒绝不支持组合 | 实验级校验 |
| 可审计导出 | 哈密顿指纹、solver 快照、parity 表 | parity / repro 脚本 |

### 4.2 化学语义与为何截断活性空间

在给定单粒子基底下，电子哈密顿量的二次量子化形式为：

$$
\hat{H}
= E_{\mathrm{nuc}}
+ \sum_{pq} h_{pq}\, a_p^\dagger a_q
+ \frac{1}{2}\sum_{pqrs} g_{pqrs}\, a_p^\dagger a_q^\dagger a_s a_r
$$

完备基下对角化等价于 Full CI，轨道与电子稍多就会使 Hilbert 空间维数无法承受。工程上必须把轨道划分为冻结芯、活性与冻结虚等区域：芯轨道在相关计算中保持双占据（闭壳图景），其贡献折叠进常数能量项；量子变分或 CASCI 只在活性自由度上展开。本模块在配置层用 `active_space` 表达这一截断，在构建层生成仅含活性自由度的有效算符，再经映射

$$
\hat{H}_{\mathrm{qubit}} = M(\hat{H}) = \sum_k c_k\, P_k
$$

得到量子比特哈密顿量。主路径 `qh` 在变分前固定（`hamiltonian_fixed_before_variational`）；嵌入模式下杂质或片段哈密顿量同样在 pre-quantum 阶段确定。变分之后的 embedding 工作流阶段默认只做审计，不改写主 `qh`。

活性空间 Hilbert 维数可作自检。闭壳 \((n_{\mathrm{e}}, n_{\mathrm{o}})\)（\(n_{\mathrm{o}}\) 为空间活性轨道数，\(n_{\mathrm{e}}\) 为偶）时，一种常用写法是 \(\binom{n_{\mathrm{o}}}{n_{\mathrm{e}}/2}^{2}\)。例如 CAS(4e, 4o) 为 \(\binom{4}{2}^{2}=36\)。若与编码维数不符，应先核对电子数定义与空间/自旋轨道计数约定。

### 4.3 平均场与经典对照

平均场阶段最常见的是 Hartree–Fock。闭壳 RHF 能量可写成密度矩阵与 Fock 矩阵的迹形式；本栈把“能跑哪些后续钩子”编码为 `SolverCapabilities`，而不是在业务代码里写死驱动名。经典对照接口在 Phase A 中统一为结构化返回，至少覆盖 hf、mp2、ccsd、casci 等键；对依赖缺失或收敛失败的方法返回不可用状态与原因，而不是直接崩溃。benchmark 选择策略可通过 `chemistry_extended.classical_benchmark_backend`（`auto|stub|pyscf|psi4`）指定，并应与 `driver_meta.upstream_classical_software_tag` 对齐，避免对照数据与实际上游脱节。

### 4.4 Phase A 收口项

| 项 | 内容 | 状态 |
|----|------|------|
| A1 | 统一经典 post-HF benchmark 接口与结构化返回 | 已交付 |
| A2 | `driver_meta` 最小字段集（分子与 PBC 路径可机读） | 已交付 |
| A3 | `active_space.strategy` 支持 manual + CAS，并写入 `active_space_recipe` | 已交付 |
| A4 | 配套测试文件与配置样例 | 已交付 |

`driver_meta` 最小字段通常包括驱动族、SCF 方法、积分表象、溶剂模型、周期性标志与 k 网格、能量记账模型、上游软件版本等，供 parity 与 Methods 表格直接引用。

### 4.5 双线路经典输入

线路 A（在线）：用户提供结构与基组，由 `scf.driver` 指向的后端现场计算平均场与积分，再构建 `PreQuantumInput`。线路 B（离线）：读取预先准备的 `classical_reference_bundle_v1` JSON，直接提供经典参考能量与量子比特哈密顿量项。两条线路在量子阶段前必须收敛到同一契约；`source`、`integral_source`、`hamiltonian_fingerprint` 等字段应能区分来源并支持审计。

### 4.6 积分约定与 OpenFermion 桥

活性空间积分导出后，本仓与 OpenFermion / Tangelo 社区常见配方对齐：双体积分在进入 `InteractionOperator` 时采用约定的转置与二分之一因子，避免出现“经典 FCI 对、量子比特对角化不对”的隐性错误。相关断言见 `tests/chem` 中积分与 Tangelo 配方对齐测试：在可安装 Tangelo 的环境中，还可进一步与 `SecondQuantizedMolecule` 的 JW 算符做数值对比。工程上这意味着经典层交付不仅是“能算出一个能量”，还包括积分指标约定可复核。用户若在外部脚本中自行拼装积分，必须遵守同一约定，否则不能拿本仓变分结果与外部 FCI 直接比。

### 4.7 嵌入功能在产品中的位置

嵌入不是默认路径。绝大多数入门与回归仍以 `embedding.mode: none` 的全局活性空间为主。嵌入的价值在于把量子资源集中到杂质或片段子空间，同时用经典环境处理其余部分。本仓已交付的是代表路径与契约：Schmidt 原子杂质生产、Mulliken 投影片段、以及 plugin 注入。密度反馈、多片段自洽、精确片段求解等能力在样例与测试中有不同程度覆盖，但对外表述应使用“代表路径可跑、契约可审计”，而不是“任意分子自动 DMET 生产”。变分后 embedding 工作流阶段若开启，默认只做审计，避免与主路径 `qh` 产生隐式双重修改。

## 5. 架构与数据流

### 5.1 五层子架构

| 层 | 目录 / 模块 | 职责 |
|----|-------------|------|
| L0 配置 | `qchem_stack.config` | 分子、SCF、活性空间、嵌入的声明与校验 |
| L1 驱动 | `chem/solvers` | 协议、注册表、各程序适配器 |
| L2 交换 | `chem/bridges` | `MolecularMeanFieldResult` → `ClassicalMeanFieldReference` |
| L3 构建 | `pre_quantum_*`、`hamiltonian*` | 积分包、映射、指纹、`PreQuantumInput` |
| L4 钩子与嵌入 | `active_space/`、`integrals/`、`embedding/`、`kernels/` | AVAS 等后端钩子；Schmidt/DMET/projection |
| 导出侧 | repro / integrations / scripts | parity、Methods、solver 快照 |

### 5.2 主数据流

```text
experiment.yaml
  → load_experiment_config（类型校验 + capabilities 门控）
  → create_solver(cfg)
  → set_physical_data + compute_mean_field
  → classical_mean_field_via_solver_bridge
  → ClassicalMeanFieldReference（含 driver_meta）
  → annotate active-space 元数据
  → resolve_pre_quantum_path / build_pre_quantum_input
  → PreQuantumInput（QubitHamiltonian + fermion_space + meta）
  → 量子与协议阶段
```

推荐业务入口是编排或 SDK（`run_pipeline_sync` / `run_pipeline_from_config`），而不是在应用代码里手写整条链。库内已有 `ExperimentConfig` 与平均场参考时，应调用 `build_pre_quantum_input`；遗留的 `molecular_hamiltonian_from_classical_reference` 仍可能可用，但会发出弃用警告。

### 5.3 Pre-quantum 分支优先级

`resolve_pre_quantum_path(cfg)` 按下列顺序择一：

1. `scf.driver == precomputed` → 离线 bundle  
2. `embedding.mode == plugin` → 分解插件积分  
3. Schmidt 生产路径（`dmet` + `schmidt_atomic_production`）  
4. Mulliken 投影片段路径（`projection`）  
5. 默认：canonical 活性空间积分包  

对应的 `source` 约定包括：`precomputed_bundle`、`embedding_plugin`、`schmidt_atomic_production`、`projection_fragment_mulliken_mo`、`canonical_active_space_integral_pack`。允许的 YAML 组合见 `docs/pre_quantum_yaml_matrix.md`。

### 5.4 `PreQuantumInput` 稳定摘要字段

管线输出中的 `out["pre_quantum_input"]` 保留完整 `hamiltonian_meta` 以兼容分析脚本，同时提供一组稳定顶层字段供 UI、API 与 Methods 优先消费：

| 字段 | 说明 |
|------|------|
| `schema` | 固定为 `pre_quantum_input_v1` |
| `source` | 进入量子前的分支来源 |
| `backend_tag` | 如 `pyscf`、`precomputed` |
| `n_qubits` | 当前量子比特数 |
| `integral_source` | 积分或 Pauli 来源标签 |
| `fermion_to_qubit_map` | JW / BK / SCBK |
| `hamiltonian_fingerprint` | 排序 Pauli 项的稳定 SHA-256 摘要前缀 |
| `reference_energy_au` / `scf_energy_au` | 经典参考总能量 |
| `n_active_orbitals` / `n_active_electrons` | 活性空间尺寸 |
| `hamiltonian_branch` | canonical / schmidt / projection / plugin / precomputed |
| `hamiltonian_fixed_before_variational` | 变分前算符是否已固定 |

`integral_source` 不应硬编码假装来自 PySCF。优先级为：显式参数大于 canonical pack provenance，再大于后端标签兜底；离线 bundle 与 decomposition plugin 使用各自来源标签。

### 5.5 维护纪律

新增经典后端时，实现 `ChemIntegralSolver`，如实填写 `SolverCapabilities`，经内置 bootstrap 或 entry point 注册，并为所用能力补测试。新增编排阶段时，只依赖 bridge / pack / capability，不直接依赖某一程序的原生类型做分支。PySCF 专属扩展应在进入统一交换物之前完成，或在错误信息中标明仍依赖原生 API。单次 pipeline run 内，`RunBuildCache` 可复用相同配置与平均场下的积分包，统计见 `out["pre_quantum_build_cache"]`。

## 6. 后端能力与注册机制

### 6.1 内置驱动

| `scf.driver` | 实现类 | 适用场景 |
|--------------|--------|----------|
| `pyscf` | `PySCFIntegralSolver` | 默认生产路径；分子与周期性、密度拟合、溶剂等较完整 |
| `psi4` | `Psi4IntegralSolver` | 跨程序对照与代表嵌入；需单独安装 |
| `precomputed` | `PrecomputedIntegralSolver` | 无现场 SCF；读 JSON bundle |

### 6.2 能力位对照

| 能力位 | PySCF | Psi4 | precomputed |
|--------|:-----:|:----:|:-----------:|
| 分子 SCF | 有 | 有 | 有（自 bundle） |
| 周期边界 SCF | 有 | Γ 点 | 无 |
| PBC k-mesh（`max>1`） | 有 | 无 | 无 |
| 受限活性空间 → qubit H | 有 | 有 | 无（bundle 直供 H） |
| AVAS 投影 | 有 | 有（导入 MO 后委托共享核） | 无 |
| Schmidt / 投影嵌入 | 有 | 有 | 无 |
| CASSCF 轨道审计 | 有 | 有 | 无 |
| RDM / NEVPT2 钩子 | 有 | 有（NEVPT2 委托共享核） | 无 |
| `get_integrals` | 有 | 有 | 无 |

管线分支与能力位的对应关系示例：全局活性空间量子比特哈密顿量要求 `supports_restricted_active_space_qubit_hamiltonian`；`strategy: avas` 要求 `supports_avas_active_space_projection`；Schmidt 杂质要求 `supports_schmidt_atomic_hamiltonian`；投影 Mulliken 要求 `supports_projection_fragment_mulliken_hamiltonian`。加载期按位门控，而不是按驱动名字字符串硬分支。

### 6.3 Psi4 科学边界（使用前必读）

Psi4 路径上，AVAS 使用导入的分子轨道跑共享 PySCF `mcscf.avas` 核，元数据中会记录来源标记；NEVPT2 类校正同样调用共享 `mrpt.NEVPT(CASCI)`，差异主要在 MO 来源。Schmidt 杂质 ERI 在 Psi4 侧通过 `MintsHelper` 与 MO 变换构造，与 PySCF `ao2mo` 路径不同。Mulliken 投影在临时改写轨道系数后应恢复，避免污染参考波函数。PBC 仅 `pbc_kpoint_mesh: [1,1,1]`；`ddcosmo` 映射为 Psi4 PCM。跨程序对照测试采用软阈值，见 `pytest -m psi4` 相关用例。

### 6.4 注册与插件扩展

```python
from qchem_stack.chem.solvers.registry import (
    create_solver,
    registered_solver_ids,
    register_solver,
)

print(registered_solver_ids())
solver = create_solver(cfg)
print(type(solver).__name__, solver.capabilities)
```

第三方后端建议独立打包，在 `pyproject.toml` 声明：

```toml
[project.entry-points."qchem_stack.chem_solvers"]
your_backend = "your_solver_plugin.solver:YourBackendIntegralSolver"
```

`your_backend` 必须与 YAML 中 `scf.driver` 对齐（规范化为小写）。entry point 可为工厂函数或带 `from_experiment_config` 的类。安装后可用 `registered_solvers_detail()` 查看来源。同名 id 默认拒绝覆盖。模板见 `chem/solvers/custom_solver_template.py` 与 `examples/solver_plugin_entrypoint_demo/`。协议检查可用 `scripts/check_solver_adapter_contract.py`。

不要在 `config/_active_space_validation.py` 中直接 import 新后端；跨能力组合放在实验级校验中，活性空间模块保持与具体 QC 包解耦。

### 6.5 与开源对照的定位

相对 Tangelo 的 `IntegralSolver`，本仓在方法命名上对齐 `set_physical_data`、`compute_mean_field`、`get_integrals` 三方法心智，但经典层与量子算法分层更严格，不把 ansatz 注册表与经典驱动混在同一抽象里。相对商业平台的“化学规格”对象模型，本仓以分层 YAML + `ExperimentConfig`、`ClassicalMeanFieldReference` 与 `PreQuantumInput` 承担声明式化学规格与进入程序构造前的交换职责。对标结论用于架构说明，不构成闭源等价宣称。

### 7.5 管线阶段与输出键（与经典相关部分）

同步管线主要阶段包括：`scf`（经典平均场）、`pre_quantum`（构建 `PreQuantumInput`）、`variational`、可选 `embedding_workflow`、可选激发态与协议收尾。成功后的核心结果键包括 `schema`（`pipeline_result_v1`）、`scf_energy`、`energy_after_variational`、`pre_quantum_input`、`energy_components`、`hamiltonian_meta`、`pre_quantum_build_cache`、`repro` 等。应用侧读取经典交接信息时，优先使用 `pre_quantum_input` 的稳定摘要字段，而不是深入解析完整 meta。

### 7.6 日常操作建议

新成员第一次接触本模块时，建议按以下顺序操作，避免一上来修改嵌入或 AVAS 导致排障困难。

第一步，确认环境。安装 `[chem,dev]` 后运行 `smoke_pipeline.py`；若本机暂时没有 PySCF，先跑 `--precomputed-only`，证明编排与量子侧入口可用，再回头补经典依赖。

第二步，只改分子或基组。复制 `example_h2.yaml`，先改键长或基组名，观察 `scf_energy` 与 `hamiltonian_fingerprint` 是否变化。指纹变化说明经典段确实重新参与了构建；若能量异常，先检查单位是 Bohr 还是 Angstrom，以及电荷多重度是否匹配。

第三步，再改活性空间。在 CAS(2,2) 基础上尝试 CAS(4,4) 的小分子样例（如水或氮气样例），确认比特数与运行时间上升符合预期。不要在未理解映射的情况下同时改 BK/SCBK 与 ansatz。

第四步，最后再换驱动或开嵌入。换 `psi4` 时保持分子与活性空间不动，只改 `driver`；开 Schmidt 或 projection 时先用仓库现成 YAML，确认能跑通后再改原子分组。

排障时优先看加载期报错（配置问题），其次看 `driver_meta` 与 `pre_quantum_input.source`（路径选错），最后才看变分能量数字。把“配置没过校验”“经典路径选错”“量子优化未收敛”三类问题分开处理，可以显著缩短定位时间。

### 7.7 与 Methods / 可复现导出的配合

若需要把经典段写入论文 Methods 或内部实验记录，推荐流程是：用代表 YAML 跑通管线或直接调用 `scripts/export_parity_criteria_table.py`，从导出表中提取 `registered_solvers`、当前驱动的 `solver_capabilities_snapshot`、`driver_meta` 关键字段，以及哈密顿指纹。不要手工抄写“使用了 PySCF”一句话了事；至少应能说明基组、SCF 方法、活性空间尺寸、映射方式与积分来源分支。离线 bundle 场景还须注明 bundle 的生成方式与 `upstream_classical_software_tag`。

## 8. 使用手册：实验配置详解

实验以 YAML 描述，经 `load_experiment_config` 转为强类型 `ExperimentConfig`。顶层须声明 `schema_version: "2"`。与经典模块直接相关的块是 `molecule`、`scf`、`active_space`、`embedding`，以及可选的 `chemistry_extended`。其余 `quantum`、`backend`、`mitigation` 等块属于下游，完整样例请复制 `configs/example_h2.yaml` 再改，避免漏字段。

### 8.1 `molecule`

该块描述几何、电荷、自旋多重度与基组。几何可内联 `coordinates`，或通过 `geometry_file` 读取结构文件（当前支持 XYZ）。二者互斥。`coordinate_unit` 取 `bohr` 或 `angstrom`。电荷与多重度必须与 `scf.method` 的自旋处理方式一致：单重态闭壳通常用 RHF；开壳自由基考虑 UHF 或 ROHF。基组写在 `molecule.basis`，不在 `scf` 中重复。ECP 等重元素设置见对应样例（如 `example_mg_lanl2dz_ecp_rhf.yaml`）。结构文件样例见 `configs/example_h2_geometry_file_xyz.yaml` 与 `configs/structures_h2.xyz`。

### 8.2 `scf`

`scf` 决定经典平均场如何计算：用哪家程序、闭壳还是开壳 HF，以及可选的收敛与加速选项。它不负责原子坐标与基组名，也不负责 VQE 迭代次数。

规范写法采用嵌套形态，顶层只保留判别键与各 driver 子块：

```yaml
scf:
  driver: pyscf
  method: RHF
  pyscf:
    max_cycle: null
    chkfile: null
    init_guess: null
    level_shift: null
    use_newton: false
    diis_space_dimension: null
    density_fit: false
    density_fit_auxbasis: null
  psi4:
    max_cycle: null
  precomputed:
    bundle_path: null
```

| 字段 | 说明 |
|------|------|
| `driver` | 注册表 id，默认 `pyscf`，加载后规范化为小写 |
| `method` | `RHF` / `ROHF` / `UHF` |
| `pyscf.*` / `psi4.*` | 仅当对应 driver 被选中时生效的控制项 |
| `precomputed.bundle_path` | 离线 bundle 路径；`driver=precomputed` 时必填 |

常用控制项含义如下。`max_cycle` 为 SCF 最大迭代轮数，难收敛体系可显式加大（如过渡金属样例中的 120）。`chkfile` 与 `init_guess: chkfile` 配合可续算。`init_guess` 还可取 `minao`、`atom`、`huckel` 等由后端定义的令牌。`level_shift` 抬高虚轨道能量以助收敛。`use_newton` 在 RHF/ROHF 上启用 Newton 求解。`diis_space_dimension` 控制 DIIS 历史长度。`density_fit` 启用密度拟合/RI；仅当其为真时可写 `density_fit_auxbasis`，否则加载失败。相关样例：`example_h2_sto3g_density_fit.yaml`、含 ECP 与密度拟合的镁/卤化氢样例。

多数 H₂ 示例只写 `driver` 与 `method` 两行，其余使用默认值即可。换后端只改 `driver`，不改变基组与几何。

### 8.3 `active_space`

平均场完成后，通常不会把全部轨道送入量子问题。`active_space` 写明活性空间多大、如何选定、以及费米子到量子比特的映射方式。

| `strategy` | 含义 |
|------------|------|
| `cas` | 默认；在配置中直接给出活性轨道数与电子数 |
| `manual` | 手写数目，并可记录 `frozen_orbitals`（从 0 起的冻结核轨道编号） |
| `avas` | 真实 AVAS 投影；需能力位与非空 AO 标签 |
| `avas_stub` | 占位策略，不执行真实投影 |

轨道与电子数目可用直观字段 `n_active_orbitals` / `n_active_electrons`，或文献常用名 `ncas` / `nelecas`。两套都写时数值必须一致。schema v2 完整示例中也可能以嵌套 `cas:` / `manual:` / `mapping:` 块出现，以当前加载器与 `example_h2.yaml` 为准。未写 `strategy` 时默认为 `cas`。

映射取值：

| 值 | 说明 |
|----|------|
| `jordan_wigner` | 默认；绝大多数示例 |
| `bravyi_kitaev` | BK 编码；默认走空间轨道费米子快捷路径 |
| `symmetry_conserving_bravyi_kitaev` | 对称性守恒 BK；比特数较 JW 少 2 |

JW 可选打开 `prefer_restricted_spatial_fermion_for_jordan_wigner` 以降低内存，或设置 `jordan_wigner_coeff_atol` 截断小系数；二者互斥。`quantum.variational_ansatz=uccsd` 时，实验级校验会限制允许的映射集合；SCBK 与 UCCSD 的组合当前不允许。部分嵌入路径仍以 JW 为主，使用 BK/SCBK 前应查阅 BK/SCBK 备忘文档。

手工 `frozen` 列表与 CAS(ncas, nelecas) 在个别教程特例中可得到相同占据图，但一般并不等价：前者可指定非连续轨道，后者通常按程序约定截取可复现的轨道块。化学上若目标活性轨道在能量序上不连续，仅写 ncas/nelecas 可能切不到目标子空间，此时应结合轨道成分或改用 AVAS。

### 8.4 AVAS 使用要点

AVAS（Atomic Valence Active Space）按给定原子轨道标签投影，挑选化学成分透明的活性分子轨道。配置上需要 `active_space.strategy: avas`，并在 `chemistry_extended.avas`（或文档所述等价字段）提供非空 `ao_labels`。加载期检查能力位与标签，不再要求 `scf.driver` 必须为 `pyscf`。PySCF 样例为 `example_h2_avas.yaml`；Psi4 样例为 `example_h2_psi4_avas.yaml`。CASSCF 轨道审计见 `example_h2_casscf_audit.yaml`。更细的理论与开源对照见仓库文档《活性空间指定与AVAS_理论实践与开源对照》。

### 8.5 `embedding`

| `mode` | 变分前是否改主 `QubitHamiltonian` | 用途 |
|--------|-----------------------------------|------|
| `none` | 否 | 默认 CAS 路径 |
| `dmet` | 是（含 Schmidt 生产） | DMET 形工作流 |
| `projection` | 是 | Mulliken 片段投影 |
| `plugin` | 是 | JSON 积分插件 |

自 nested schema v2 起，不再支持扁平旧键（如顶层 `schmidt_*`），应改用 `embedding.dmet.schmidt.*`、`embedding.projection.*`、`embedding.plugin.*` 等子块。错误 mode 下出现不应有的子块会在加载时报错。共享顶层还可设置 `embedding_input_representation`（`mo` / `ao` / `lowdin_orth_ao`）、`n_scf_cycles_embedding`、`classical_reference_method` 等。

Schmidt 生产路径要求 `scf.method: RHF`。`dmet.hamiltonian_source` 常见取值包括 `parity_stub`、`whole_active_system`、`schmidt_atomic_production`。`dmet_max_cycles` 受 schema 上限与生产 guard 上限双重约束。投影模式下，当 `quantum_hamiltonian: fragment_mulliken_mo` 时必须提供合法 `fragment_atom_indices`。

### 8.6 加载期校验索引

| 校验 | 作用 |
|------|------|
| 驱动已注册 | 未知 `scf.driver` 直接失败 |
| 能力位与路径匹配 | 所选嵌入/活性空间是否被当前后端支持 |
| AVAS 标签与能力 | `strategy: avas` 的前置条件 |
| precomputed 与 live 钩子互斥 | 离线驱动禁止现场 AVAS/嵌入钩子 |
| PBC 与 CASSCF 钩子互斥 | 周期性路径限制 |
| Schmidt 与 RHF / 循环上界 | 嵌入生产路径约束 |
| 密度拟合与辅助基配套 | 仅 `density_fit: true` 时可写 auxbasis |

用途是确认统一入口与元数据，而不是切换量子算法。加载后应能看到一致的活性空间尺寸，并在产物中留下 `active_space_recipe` 一类可追溯信息。

### 9.3 路径三：Psi4 次后端

配置：`example_h2_psi4_rhf_sto3g.yaml`。将 `scf.driver` 设为 `psi4`，分子与活性空间与对照样例保持一致。运行前确认 Psi4 已安装。延伸样例：`example_h2_psi4_schmidt_dmet.yaml`、`example_h2_psi4_avas.yaml`。可将同一分子在 PySCF 与 Psi4 下得到的 `scf_energy` 与哈密顿指纹做对照，但解释差异时应参考软阈值测试，而不是要求逐位一致。

### 9.4 路径四：变分能量相对 SCF 的对照

配置：`example_h2_uccsd.yaml`。脚本：`examples/tutorial_04_uccsd_below_scf.py`。在同一套活性空间哈密顿量上打印 `scf_energy` 与 `energy_after_variational`，用于演示变分结果相对 RHF 参考的下降（脚本内含数值裕量）。若经典段积分约定或粒子数投影不正确，该演示会失真，因此它也是经典—量子交接的间接验收手段。

### 9.5 路径五：周期性、密度拟合与稍大活性空间

| 配置 | 用途 |
|------|------|
| `example_h2_pbc_gamma.yaml` | Γ 点周期性 |
| `example_h2_sto3g_density_fit.yaml` | 密度拟合 |
| `example_n2_sto3g_cas44.yaml` / `example_h2o_sto3g_cas44.yaml` | 稍大 CAS |
| `example_fe_sto3g_helike_rhf_cas22.yaml` | 高离化 Fe、CAS(2,2)，关注收敛与参考对齐 |

Fe 样例用于可运行的小规模对照，不等价于中性铁簇或 Fe4N2 工业案例。

### 9.6 顺序烟测与结果解读

```bash
python examples/run_all_smoke.py
```

该脚本顺序运行 tutorial 01–04，任一非零退出码即失败。解读结果时注意：`scf_energy` 是经典参考总能量；`energy_after_variational` 是变分基态能量；二者比较必须建立在同一活性空间哈密顿量与正确粒子数扇区之上。`hamiltonian_fingerprint` 可用于配置变更前后的回归比对。

### 9.7 现场演示建议流程（约 15–20 分钟）

若用于组会、验收答辩或合作方演示，可采用下面的固定流程，减少临场改配置带来的不确定性。

1. **环境确认（2 分钟）**：展示 `registered_solver_ids()` 输出中包含 `pyscf`；说明 Psi4、precomputed 为可选。  
2. **主路径（5 分钟）**：运行 `example_h2.yaml` 或 tutorial 01，展示 `scf_energy`、`pre_quantum_input.source`、指纹前缀。说明此时量子侧并不知道底层是哪家程序。  
3. **双线路（3 分钟）**：切换到 `example_h2_precomputed_bundle.yaml`，强调同一 `PreQuantumInput` 契约、不同 `source`。  
4. **多后端或嵌入二选一（5 分钟）**：有 Psi4 环境则跑 `example_h2_psi4_rhf_sto3g.yaml` 做能量对照；否则跑 `example_h4_schmidt_multifragment.yaml` 或 plugin 玩具样例，说明嵌入在变分前改写了主哈密顿量。  
5. **验收证据（3 分钟）**：展示近期 `pytest tests/chem/` 与 `check_parity_export_sample.py` 的通过记录，或当场抽跑 registry 契约测试。

演示前应冻结所用提交哈希与环境说明，避免“我这边能跑你那边不能”的争论停留在口头层面。

### 9.8 从零编写一份自己的实验配置

对已经熟悉 YAML 的用户，可按下列检查单自建配置：

1. 从最接近目标的 `example_*.yaml` 复制，而不是空白新建。  
2. 修改 `experiment_id` 与 `random_seed`（若后续量子采样需要可复现种子）。  
3. 改 `molecule`：符号、坐标或 `geometry_file`、电荷、多重度、基组。  
4. 确认 `scf.driver` 与本机依赖一致；需要对照时再复制一份改 `psi4`。  
5. 设定活性空间尺寸与映射；H₂ 入门保持 (2,2) 与 JW。  
6. `embedding.mode` 默认 `none`；只有明确要做碎片问题时再改。  
7. 保留完整的 `quantum` / `backend` 块，先用 statevector 一类本地后端验证经典段。  
8. 先 `load_experiment_config` 只加载不跑，确认无校验错误；再跑管线。  
9. 记录 `scf_energy` 与指纹，作为后续改动的基线。

## 10. 使用手册：嵌入、离线输入与扩展

### 10.1 离线 precomputed

```yaml
scf:
  driver: precomputed
  method: RHF
  precomputed:
    bundle_path: precomputed_classical_reference_h2.json
```

样例：`configs/example_h2_precomputed_bundle.yaml` 与 `configs/precomputed_classical_reference_h2.json`。Bundle 至少包含 `classical_reference`（能量、轨道能、`driver_meta`）与 `pre_quantum_input.qubit_hamiltonian`（`n_qubits` 与 `terms`）。Pauli 标签支持紧凑写法（`"ZZ"`，长度等于比特数）与索引写法（`"Z0 Z1"`）。

生成工具：

```bash
python scripts/build_precomputed_bundle.py \
  --decomposition-json configs/decomposition_plugin_toy_integrals.json \
  --output configs/precomputed_classical_reference_h2.json \
  --e-tot -1.116708174 \
  --mo-energy=-0.580628,0.676341
```

路径相对于 YAML 所在目录解析。`driver=precomputed` 时路径必填；其他 driver 不得填写 bundle。离线线路适合无经典依赖的 CI、固定参考能量对照，以及把经典计算与量子阶段拆到不同机器上的批处理。不适合需要现场 AVAS、CASSCF 或嵌入 live 钩子的场景。

### 10.2 DMET / Schmidt

代表配置：`example_h4_dmet_self_consistent.yaml`、`example_h4_schmidt_multifragment.yaml`、`example_h2_psi4_schmidt_dmet.yaml`。当 `hamiltonian_source: schmidt_atomic_production` 时，由 SCF 密度构造 Schmidt 杂质与 bath，并生成杂质 JW 哈密顿量作为主变分目标。多片段时通过 `multi_fragment_atom_groups` 等字段描述原子分组与主片段索引。使用前确认后端具备 Schmidt 能力位，且平均场为 RHF。

### 10.3 投影嵌入

代表配置：`example_h4_projection_mulliken.yaml`。`mode: projection` 下按 Mulliken 片段选取构造片段哈密顿量。`fragment_atom_indices` 必须落在分子原子编号范围内。可与 `classical_reference_method` 等字段配合做对照记账，具体键以嵌入配置说明与 DMET/parity 技术文档为准。

### 10.4 分解插件

```yaml
embedding:
  mode: plugin
  plugin:
    name: uniform_fragment_guess
    json_path: configs/decomposition_plugin_toy_integrals.json
```

样例：`example_decomposition_plugin_toy.yaml`。该路径用于契约级哈密顿量注入与管线连通验证。扩展新插件时走注册机制，不修改 orchestration 内核选路逻辑。

### 10.5 从旧 API 迁移

若外部脚本仍引用 `PySCFDriver`，应按迁移指南改为：

```python
from qchem_stack.config import load_experiment_config
from qchem_stack.chem.bridges.facade import classical_mean_field_reference_from_config
from qchem_stack.chem.pre_quantum_build import build_pre_quantum_input

cfg = load_experiment_config("configs/example_h2.yaml")
reference = classical_mean_field_reference_from_config(cfg)
pqi = build_pre_quantum_input(cfg, reference)
```

能力探测使用 `SolverCapabilities`，不要对 PySCF 原生分子对象做 `isinstance` 选路。

### 10.6 第三方 solver 接入步骤（摘要）

1. 实现 `ChemIntegralSolver`（至少 `from_experiment_config`、`compute_mean_field`、`capabilities`）。  
2. 如实填写能力位；适配器契约检查会做一致性校验。  
3. 内置注册或 entry point 注册。  
4. YAML 中设置 `scf.driver`。  
5. 为所用能力补测试；涉及 AVAS 时实现投影钩子后再将对应能力位置真。  
6. 用 `check_solver_adapter_contract.py` 做结构检查，再跑代表 YAML 管线。

## 12. 已知限制、风险与后续工作

### 12.1 已知限制

1. Psi4 对 `max(pbc_kpoint_mesh)>1` 未完整支持；AVAS、NEVPT2 等存在共享核委托，需在 Methods 中写明。  
2. 嵌入与投影部分路径仍以 Jordan–Wigner 为主；SCBK 与部分 ansatz 组合受校验限制。  
3. `precomputed` 不提供 live 积分与嵌入钩子。  
4. 大体系、溶剂、密度拟合具备样例，但不构成工业默认流程。  
5. 仓库没有可一键运行的 Fe4N2 级商业闭源栈式案例；开放栈以 H₂、H₄、N₂、H₂O 等小体系为主。  
6. 许可证方面，PySCF 与 Psi4 由用户环境自行安装；本仓分发遵循根目录许可证，交付物不含闭源 SDK 或 API 密钥。

### 12.2 风险与缓解

| 风险 | 缓解 |
|------|------|
| 可选依赖导致 CI 假失败 | Psi4 用 optional 标记；主 CI 以 PySCF 为准 |
| 数值等价叙事漂移 | 只宣称能力与契约，不宣称闭源或跨程序全方法等价 |
| 大量 YAML 维护负担 | 验收强制代表子集；其余作为语料保留 |
| 元数据契约与嵌入任务耦合返工 | 先冻结 `driver_meta` 与 bridge 契约，再扩展嵌入 |

### 12.3 建议纳入后续迭代

| 编号 | 内容 |
|------|------|
| R1 | AVAS 全自动与 CASSCF 轨道优化审计生产化 |
| R2 | Psi4 受限活性空间积分闭合，减少对 PySCF 委托 |
| R3 | DMET/Schmidt 能量账本与 `epistemic_bound` 统一 SPI |
| R4 | NEVPT2/AC0 校正接入 classical benchmarks 生产开关 |
| R5 | decomposition plugin 多 fragment 生产样例与 CI 必选化 |
| R6 | 第三方 solver 官方插件样例（不宣称数值等价） |

量子算法广度、缓解执行模型、编译与云作业闭环属于后续阶段，不在本模块交付义务内。

### 12.4 交付收口陈述

综合源码、测试、配置样例与既有契约文档，经典化学模块本期可按如下口径交接：平台已具备以 `ChemIntegralSolver` 为核心的多后端经典入口；PySCF 主路径完成从配置到 `PreQuantumInput` 的生产闭环；Psi4 与 precomputed 证明同一契约可扩展；活性空间、映射、嵌入代表路径与经典对照具备可运行证据；能力门控与 `driver_meta` 支撑 Methods 级审计。使用方应优先通过 YAML 与管线入口操作，集成方应优先通过注册表与 bridge 扩展，双方均不应再把 PySCF 当作架构特权依赖。

| parity export | Methods / 对照用结构化导出 |
| Phase A | PySCF 继承改造：benchmarks + meta + active-space 入口 |
| 双线路 | 在线 SCF 与离线 precomputed 两条经典输入 |

### 附录 D：常见问题

| 现象 | 处理 |
|------|------|
| `driver=precomputed` 报错缺路径 | 设置 `scf.precomputed.bundle_path` |
| 非 precomputed 却填写 bundle | 删除 bundle 字段或改 driver |
| 选择了 AVAS 但加载失败 | 检查能力位与 AO 标签是否非空 |
| Psi4 测试被跳过 | 使用已安装 Psi4 的解释器执行 `pytest -m psi4` |
| `geometry_file` 与 `coordinates` 同时出现 | 二者互斥，只保留一种 |
| 结构文件后缀不支持 | 当前仅 XYZ |
| 嵌入仍写 flat 旧键 | 改为 nested 子块 |
| 密度拟合写了 auxbasis 却未开 density_fit | 先设 `density_fit: true` |
| 编排代码直接 import PySCF 选路 | 改为 `create_solver` + capabilities |
| 变分能量与 SCF 比较“不合理” | 确认同一活性空间、映射与粒子数扇区；先看 fingerprint 与 `scf_energy` |
| 找不到 `PySCFDriver` | 已移除；改用本文第 10.5 节迁移路径 |

补充说明如下。

**配置能加载但 SCF 不收敛。** 先核对多重度与 `method`，再增大 `max_cycle`，必要时尝试 `level_shift` 或 `use_newton`。过渡金属与开壳体系不要照搬 H₂ 默认值。检查点续算适合本地调试，不适合作为 CI 必选路径。

**指纹变了但能量几乎不变。** 可能是 Pauli 项排序、截断阈值或 meta 附属信息发生变化，不一定代表化学能量变了。应以 `scf_energy` 与变分能量为主判据，指纹用于回归侦测“构建链是否被意外改动”。

**同一 YAML 在两台机器结果不同。** 优先核对依赖版本（尤其 PySCF）、坐标单位、随机种子与是否误用了不同 bundle。经典 SCF 在相同输入下应高度一致；若差异出现在变分段，再查后端与优化器设置。

**想把 ORCA 接进来。** 本期不提供数值主路径。正确做法是按第 10.6 节做插件：实现协议、声明能力、entry point 注册，并在文档中写明哪些能力为原生、哪些为委托或未实现。在未完成对照测试前，不要在对外材料中写“已支持 ORCA 全功能”。

**嵌入跑通但不知如何解释能量。** Schmidt/DMET 路径的能量记账与全局 CAS 不同，不能直接拿杂质变分能量与全分子 RHF 做简单高低比较。应阅读嵌入配置说明与 DMET/parity 技术文档中的账本字段，并在报告中写明 `hamiltonian_branch` 与 `integral_source`。

**文档与站内 Docusaurus 不一致。** 以源码与加载期校验为准，其次以 `docs/` 下契约文档为准；站内页面若滞后，应提文档修订，而不是改业务代码去迁就过时截图。
