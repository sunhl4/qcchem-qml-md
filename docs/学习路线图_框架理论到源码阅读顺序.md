## 二、实操习惯（强烈建议固定下来）

1. **锚定一条配置**：从 `configs/example_h2.yaml` 开始；需要激发/长链时再打开 `configs/example_h2_excited_smoke.yaml` 或 README 中的 `tutorial_chain_h2.yaml`。**离线经典 / precomputed**：对照 [技术文档_双线路经典输入与统一PreQuantumInput契约.md](技术文档_双线路经典输入与统一PreQuantumInput契约.md) 与 `tests/test_pipeline_precomputed_lane.py`、`tests/test_pre_quantum_input_contract.py`。
2. **YAML + 流水线对照**：开着 YAML，在 **`orchestration/pipeline.py`** 里跟踪 `run_pipeline_sync` / `run_pipeline_from_config`，同时用下列模块对齐「阶段边界」（避免只在单文件里迷路）：
   - `orchestration/stage_execution.py`（SCF / pre-quantum 阶段runner）
   - `orchestration/scf_stage.py`（参考态、活性空间 refinement、能力查询）
   - `orchestration/precomputed_stage.py`（`scf.driver=precomputed`、bundle 解析与校验）
   - `orchestration/pre_quantum_stage.py`（哈密顿量构建、`PreQuantumInput` 组装）
   - `orchestration/stages.py`（`ScfStageArtifacts` / `PreQuantumStageArtifacts`）
3. **测试当地图**：对每个子包，并行打开 `tests/test_*` 中同名前缀用例（如 `test_pyscf_*`、`test_fermion_*`、`test_backend_*`、`test_orchestration_*`、`test_pipeline_precomputed_lane.py`、`test_decomposition_plugin_pipeline.py`）。
4. **对齐 CI**：根目录 [.github/workflows/ci.yml](../.github/workflows/ci.yml) + `scripts/smoke_pipeline.py` —— 官方认定的主路径与 marker（如 `l1_excited`、`l1_md_ml`、`l3`）。

## 三、源码阅读顺序（自下而上依赖，编排最后精读总装）

**架构原则**（摘自 ENGINEERING_ARCHITECTURE）：算法与 driver **不 import** orchestration；orchestration 组装下层。读书顺序应与依赖方向一致。**经典侧两条入口**（在线求解器 vs 离线 bundle）在量子阶段前都必须变成 **`PreQuantumInput`**。

### 阶段 0：拓扑与契约

| 序号 | 路径（均在 `src/qchem_stack/` 下） | 说明 |
|------|-----------------------------------|------|
| 0.1 | `__init__.py`、`exceptions.py` | 包边界与异常 taxonomy |
| 0.2 | **`config/`**（入口 `config/__init__.py`，深读 **`config/experiment.py`**（`ExperimentConfig`）、**`config/io.py`**（`load_experiment_config` 等）） | 配置已不是单文件顶层 `config.py` —— **从包入口 import**，子模块按领域拆分（molecule/scf/active_space/quantum/embedding/…）；校验分层约定见 [`config_校验分层约定.md`](config_校验分层约定.md)。 |
| 0.3 | `repro/`（尤其 `export.py`） | 严格 JSON 导出 |
| 0.4 | **`protocols/product_contract.py`**、`contracts/schema_ids.py`（必要时） | **`product_gap_categories()`**、`PRODUCT_CAPABILITY_MAP`、parity 风格导出的 **`PARITY_EXPORT_V3_STABLE_KEYS`**、Mitigation/Open‑stack bundle 字面量等与 **控制台 / `GET /v1/meta/capability-surface`** 同源；运行时 Pauli **协议状态机**仍在 **`protocols/protocol.py`**。**`parity_snapshot` 键集合**不再有单一 frozenset 注册表——见 **`技术文档_DMET与parity_snapshot开放契约.md` §3b** 更新说明 |
| 0.5 | **`chem/pre_quantum_input.py`** | 量子阶段前统一契约 `PreQuantumInput`、`as_summary_dict()`；可与 [技术文档_双线路经典输入与统一PreQuantumInput契约.md](技术文档_双线路经典输入与统一PreQuantumInput契约.md) 对照读。 |

读完配置入口后浏览 `configs/` 中 2～3 个 YAML，建立「字段 → 分支」心智模型（含 `scf.driver` 是否在 `precomputed`）。

### 阶段 1：经典化学 `chem/`（数值主路径）

| 序号 | 建议顺序 | 说明 |
|------|----------|------|

| 1.3 | `chem/bridges/` | `mean_field_reference.py`、`canonical_integral_pack.py`、`facade.py`、`interchange.py`、`protocol.py` 等 —— **交换层 + `CanonicalActiveSpaceIntegralPack`** |
| 1.4 | **`chem/precomputed_bundle.py`** | bundle 路径解析、manifest、与 `PreQuantumInput` 衔接 |
| 1.5 | `chem/drivers/pyscf_driver.py`（及 **`chem/integrals/`**、**`chem/systems/`**） | PySCF façade；重计算拆到 `integrals`、`systems`（与 ENGINEERING「PySCF 边界拆分」一致） |

## 四、「每个文件都学到」的高效策略

仓库内 `src/qchem_stack` 文件多，**不建议按字母表线性通读**。推荐：

1. **严格按上表依赖顺序**，避免一上来死磕 `pipeline.py` 而失去全局；**编排层已拆模块**，先把 `scf_stage` / `pre_quantum_stage` / `precomputed_stage` 与 **`PreQuantumInput`** 对上号再读总 pipeline。
2. **每读完一个目录，用对应 `tests/` 前缀用例收口**。
3. **脚本验证**：本地 `pip install -e ".[dev]"`，跑 `scripts/smoke_pipeline.py` 与 README 中的 pytest 子集。
4. **文档站**（人用叙事）：[docusaurus-site/README.md](../docusaurus-site/README.md)；与 `docs/` 母稿互补，非替代。

## 五、自选深化路线（第二轮精读时可四选一作为主轴）

学完阶段 0–5 的公共骨架后，可专攻一条：

- **主轴 A**：HF + 活性空间 + UCC/VQE + Pauli protocol（最短闭环）
- **主轴 B**：激发态（VQD/QSE/SCEOM）+ 对应 `quantum/` 与 `tests/test_excited_*`
- **主轴 C**：TKET / 编译 / 资源行 + `backends/` + CircuitIR 技术文档
- **主轴 D**：Jobs + SQLite + HTTP API + `repro` 下载路径 + **双线路经典入口**（`precomputed_bundle` ↔ `PreQuantumInput`）

每条主轴都可再展开为「15～25 个文件的精读 checklist」——建议在你选定主轴后，用 `grep`/`rg` 从 `configs/*.yaml` 和 **`pre_quantum_stage.py` / `pipeline.py`** 拉出实际调用链，自动生成个人 checklist。
