## 二、实操习惯（强烈建议固定下来）

1. **锚定一条配置**：从 `configs/example_h2.yaml` 开始；需要激发/长链时再打开 `configs/example_h2_excited_smoke.yaml` 或 README 中的 `tutorial_inquanto_chain_h2.yaml`。
2. **YAML + 流水线对照**：开着 YAML，在 `orchestration/pipeline.py` 中跟踪 `run_pipeline_sync` 各阶段（SCF → Hamiltonian → variational → 可选激发/Pauli/jobs）。
3. **测试当地图**：对每个子包，_parallel_ 打开 `tests/test_*` 中同名前缀用例（如 `test_pyscf_*`、`test_fermion_*`、`test_backend_*`、`test_orchestration_*`）。
4. **对齐 CI**：根目录 [.github/workflows/ci.yml](../.github/workflows/ci.yml) + `scripts/smoke_pipeline.py` —— 官方认定的主路径与 marker（如 `l1_excited`、`l1_md_ml`、`l3`）。

## 三、源码阅读顺序（自下而上依赖，最后读编排）

**架构原则**（摘自 ENGINEERING_ARCHITECTURE）：算法与 driver **不 import** orchestration；orchestration 组装下层。读书顺序应与依赖方向一致。

### 阶段 0：拓扑与契约

| 序号 | 路径（均在 `src/qchem_stack/` 下） | 说明 |
|------|-----------------------------------|------|
| 0.1 | `__init__.py`、`exceptions.py` | 包边界与异常 taxonomy |
| 0.2 | **`config.py`** | `ExperimentConfig`、`load_experiment_config` —— 单列最高优先级 |
| 0.3 | `repro/`（尤其 `export.py`） | 严格 JSON 导出 |
| 0.4 | `protocols/inquanto_contract.py` | `repro`/parity/run_summary 等 key  whitelist 契约 |

读完 `config.py` 后浏览 `configs/` 中 2～3 个 YAML，建立「字段 → 分支」心智模型。

### 阶段 1：经典化学 `chem/`（数值主路径）

| 序号 | 建议顺序 | 说明 |
|------|----------|------|
| 1.1 | `chem/solvers/registry.py`、`create_solver` |  Solver 入口 |
| 1.2 | `chem/solvers/pyscf_solver.py`（及 registry 中其它 backend） | 当前 CI 主线多为 PySCF |
| 1.3 | `chem/bridges/` | `mean_field_reference.py`、`canonical_integral_pack.py`、`facade.py` 等；统一经典接口 |
| 1.4 | `chem/drivers/pyscf_driver.py` | Driver 路径（若仍直接使用） |
| 1.5 | `chem/hamiltonian.py`、`chem/active_space/` | qubit Hamiltonian、JW/BK/SCBK、活性空间 |
| 1.6 | `chem/embedding/` | DMET、Schmidt（用到再精读） |

**测试线索**：`tests/test_pyscf_solver_adapter.py`、`test_fermion_qubit_mapping.py`、`test_hamiltonian_fingerprint.py`、`test_restricted_*` 等。

### 阶段 2：量子算法 `quantum/`

| 序号 | 建议顺序 | 说明 |
|------|----------|------|
| 2.1 | `quantum/algorithms/` | 与 `cfg.quantum.algorithm` 对应 |
| 2.2 | `quantum/variational_plugins/` | 变分插件与扩展点 |
| 2.3 | `quantum/qse_transition.py` 等 | 激发 / QSE 相关（按 YAML 选读） |

**测试线索**：`tests/test_adapt_*`、`test_variational_*`、`test_excited_*`、`test_qpe_*`。

**文档交叉**：`docs/UCC_hf参考下单激发梯度_Brillouin与优化实践.md`、VQD/QSE 技术文档。

### 阶段 3：后端与协议 `backends/` + `protocols/`

| 序号 | 建议顺序 | 说明 |
|------|----------|------|

| 3.3 | `backends/compile_passes.py`、`pytket_bridge.py`（若装 pytket） | 编译与资源度量 |

**测试线索**：`tests/test_backend_conformance.py`、`test_executor_*`、`test_pauli_*`。

### 阶段 4：误差缓解与张量网络（按需要）

| 包 | 说明 |

### 阶段 5：编排、作业、可选 API `orchestration/` + `jobs/` + `api/`

## 四、「每个文件都学到」的高效策略

仓库内 `src/qchem_stack` 文件多，**不建议按字母表线性通读**。推荐：

1. **严格按上表依赖顺序**，避免一上来死磕 `pipeline.py` 而失去全局。
2. **每读完一个目录，用对应 `tests/` 前缀用例收口**。
3. **脚本验证**：本地 `pip install -e ".[dev]"`，跑 `scripts/smoke_pipeline.py` 与 README 中的 pytest 子集。
4. **文档站**（人用叙事）：[docusaurus-site/README.md](../docusaurus-site/README.md)；部分自动化仍指向 [docs-site/README.md](../docs-site/README.md) —— 与 `docs/` 母稿互补，非替代。

## 五、自选深化路线（第二轮精读时可四选一作为主轴）

学完阶段 0–5 的公共骨架后，可专攻一条：

- **主轴 A**：HF + 活性空间 + UCC/VQE + Pauli protocol（最短闭环）
- **主轴 B**：激发态（VQD/QSE/SCEOM）+ 对应 `quantum/` 与 `tests/test_excited_*`
- **主轴 C**：TKET / 编译 / 资源行 + `backends/` + CircuitIR 技术文档
- **主轴 D**：Jobs + SQLite + HTTP API + `repro` 下载路径

每条主轴都可再展开为「15～25 个文件的精读 checklist」——建议在你选定主轴后，用 `grep`/`rg` 从 `configs/*.yaml` 和 `pipeline.py` 拉出实际调用链，自动生成个人 checklist。
