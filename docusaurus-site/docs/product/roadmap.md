# 路线图（Roadmap）

这页维护“产品能力推进顺序”，重点是**用户可见价值**和**维护成本可控**。

## 当前阶段目标

1. 文档从“展示型”升级为“手册型”（可运行、可验证、可维护）
2. 稳定 P1-P4 核心路径（配置 -> 运行 -> 作业 -> 复现）
3. 让教程、参考、对标三套内容互相可追溯

## 近期（0-2 个迭代）

- 完成核心页面重写：产品、指南、教程、参考、云与对标
- 把教程统一成“目标 -> 前置 -> 步骤 -> 验证 -> 常见问题”
- 把参考页统一成“接口/字段/状态机/错误语义”结构
- 清理旧链接与占位页，减少导航噪声

## 中期（2-6 个迭代）

- 增补高频场景教程：切后端、异步 HTTP、ZNE、projection
- 完善运维面文档：队列堆积诊断、失败恢复、日志与告警
- 把 `scripts/` 的实际能力映射到文档（含适用场景）
- 构建“新功能最少文档要求”清单，避免再次占位化

## 长期（6+ 个迭代）

- 形成模块级契约文档（按 `src/qchem_stack/*` 边界组织）
- 引入版本化发布说明：能力变化、兼容性、迁移指南
- 逐步完善多租户与配额治理文档（在非商业云假设下）

## 验收标准（文档层）

- 任一顶级入口页都能引导用户完成“下一步动作”
- 任一教程都能在本仓库环境中复现
- 任一 `partial` 对标项都能追溯到计划或证据页
- 新成员可在 30 分钟内定位：配置入口、运行入口、调试入口
